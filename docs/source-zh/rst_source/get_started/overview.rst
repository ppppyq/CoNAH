CoNAH 简介
=============

具身智能体在真实物理世界中的协同探索挑战
-----------------------------------------

面向真实三维物理世界的 **具身智能（Embodied Intelligence）**——例如未知复杂室内场景的协同探索、长程视觉语言导航、多机搜救与大范围环境巡检——要求智能体通过第一视角传感器持续感知环境、构建空间记忆并执行物理动作。当任务规模超出单台机器人的感知视野、行动半径与算力续航时，多智能体协同探索成为必然选择。

然而，当具身智能从单机走向真实多机协同探索时，现有框架普遍面临两类根本瓶颈：

1. **脱离真实通信约束的协同假设** ：大量多机仿真与算法框架默认智能体之间可以“瞬时、零丢包、无限带宽”地共享全局地图或高清图像，回避了物理世界中客观存在的 **带宽争抢、传播与排队时延、墙体遮挡衰减（NLOS）、信号覆盖盲区与间歇性断联** 。一旦进入真实复杂建筑或园区，强依赖理想通信的协同探索策略便会迅速失效。
2. **割裂了移动机器人与网络基础设施（AP / RAN）的具身协同** ：在真实空间中， **Wi-Fi AP、5G RAN（无线接入网）与边缘节点同样扎根于物理世界**——它们拥有确定的三维空间位置、天线覆盖范围、物理层射频感知（CSI / RSSI / 频谱状态）以及资源调度与波束/转发控制能力。将 AP / RAN 排除在智能体体系之外、仅视作透明管道，使系统无法在协同探索中联合调度“物理运动”与“无线通信”。

**CoNAH (Communication-Native Agentic Harness)** 将 **移动机器人** 与 **AP / RAN 基础设施** 统一视为广义的 **异构具身智能体** ，在真实非理想无线通信环境下，把感知、推理、空间记忆、物理执行与 **模块化通信能力** 整合进一套标准化的智能体控制底座。

四大核心设计原则
------------------

1. **广义具身视角：移动机器人与 AP / RAN 统一接入 Harness**
   CoNAH 不仅编排移动机器人（轮式底盘、无人机、室内导航机器人），更将 **Wi-Fi AP、5G RAN 与边缘节点定义为广义具身智能体的一种** 并直接接入 Harness：移动机器人通过相机、雷达与运动执行器探索物理空间；AP / RAN 节点则立足自身物理位置，通过射频感知、上/下行资源调度、断联盲区缓存转发（Store-and-Forward）、语义压缩与算力卸载，与移动机器人共同完成长程协同探索任务。系统原生兼容 **Wi-Fi / 5G 基础设施、点对点直连（D2D / Mesh）及混合中继** 拓扑。

2. **面向真实非理想通信的协同探索（Impairment-Aware Collaboration）**
   无线信道与重力、墙体一样属于 **外部物理环境** 的客观约束（存在带宽瓶颈、丢包、时延抖动、穿墙衰减与覆盖盲区）。CoNAH 不掩盖这些不理想性，而是让智能体在探索过程中显式感知链路状态与通信代价（如精确计量 ``Envelope`` 字节开销），进而做出通信原生的具身决策——例如在弱网区压缩记忆增量、在盲区先本地自主探索并缓存发现、或在关键协同节点主动移动至信号覆盖区完成同步。

3. **可插拔的通信模块与通信能力（Pluggable Communication Modules & Capabilities）**
   从 Harness 视角看，智能体可按需插拔的是 **通信模块与通信能力** （如 Wi-Fi 接入、5G/RAN 接口、USRP 软件无线电收发、定向/广播通信工具、链路感知、语义编解码与中继转发能力）。所有通信能力均与运动、感知能力一样以标准 Tool（如 ``comm_send`` 、 ``comm_broadcast`` 、 ``comm_poll`` 、 ``comm_status`` ）挂载至节点 ``Toolkit`` ，面向统一的 ``CommEndpoint`` 抽象编程，实现从本机仿真环境到真实 **Wi-Fi / 5G / USRP** 硬件的零代码 Sim2Real 迁移。

4. **独立闭环与可验证回执审计（Isolated Loops & Verifiable Receipts）**
   每个具身节点运行独立的 ``AgentSession`` 、 ``Planner`` 与本地空间拓扑记忆（ ``WorldGraph`` ），通过标准本机 RPC 与底层仿真器或硬件驱动解耦。 ``HarnessRuntime`` 为每一次物理动作（ ``WORLD_MUTATING`` ）与每一次通信发射（ ``NETWORK_TX`` ）自动签发不可伪造的回执（ ``Receipt`` ），全程审计观测新鲜度与零违规闭环（ ``violations == 0`` ），并严格隔离服务端评测真值。
