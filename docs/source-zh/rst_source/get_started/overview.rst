CoNAH 简介
=============

为什么需要“通信原生”的多机具身智能框架？
-----------------------------------------

在真实物理世界（室内长程搜索、仓储巡检、灾后救援）中，单台机器人的感知视野、运动效率与算力续航均有限，多机协同是必然趋势。然而，现有具身智能框架在走向真实多机部署时，普遍存在两类根本短板：

1. **忽略真实通信条件的不理想性**：多数多智能体仿真与评测脚本默认节点之间可以“瞬时、零丢包、无限带宽”地共享全局内存或传输高清图像，完全回避了真实无线网络中的 **带宽争抢、传播与排队时延、穿墙衰减（NLOS）、信号覆盖盲区与间歇性断联**。一旦迁移到真实环境，强依赖高频同步的策略往往立刻失效。
2. **割裂了具身节点与网络基础设施节点**：真实部署中，多机互联并不局限于纯点对点自组网，更常见的是依托 **Wi-Fi AP、5G 基站与边缘服务器（MEC）**，或在信号盲区结合自组网中继。但传统框架把网络基础设施当成不可见的“透明管道”，没有让 **AP / 边缘节点本身作为一等节点接入 Harness** 参与协同调度、断联缓存与语义压缩。

**CoNAH (Communication-Native Agentic Harness)** 围绕 **面向真实非理想通信、拓扑无关、全节点可编排** 的设计哲学构建，将无线通信从“隐式假设”提升为智能体可感知、可决策、可审计的一等公民原语。

四大核心设计原则
------------------

1. **直面非理想通信条件（Impairment-First）**
   所有跨节点交互均必须封装为标准字节流信封（ ``Envelope`` ），经过可插拔无线信道模型（ ``ChannelModel`` ）精确计量字节开销，并显式建模 **MTU 上限、令牌桶带宽限速、随机丢包、延迟抖动、穿墙衰减与覆盖盲区**。智能体可通过 ``comm_status`` 感知链路质量，主动调整通信内容与探索策略。

2. **拓扑无关与 AP / 边缘节点接入（Topology-Agnostic & Infrastructure-as-a-Node）**
   CoNAH 不强制限定必须采用纯分布式 P2P 拓扑，而是原生支持 **Wi-Fi AP / 5G 基础设施模式、点对点直连（D2D / Mesh）以及混合中继模式**。更重要的是，**AP / 5G 边缘节点本身也可以作为一个独立节点接入 Harness**，在系统中承担上/下行汇聚转发、盲区断联期间的缓存补发（Store-and-Forward）、拥塞时的语义摘要压缩、全局任务板协调乃至重型视觉/大模型算力卸载。

3. **节点执行解耦与 Sim2Real 同构（Service-Oriented & Sim2Real）**
   每个节点拥有独立运行的 ``AgentSession``、``Toolkit`` 与本地记忆（ ``WorldGraph`` ），通过标准本机 RPC 与底层仿真器或硬件驱动解耦。上层智能体统一面向 ``CommEndpoint`` 编程，底层可在软件信道仿真（ ``LocalhostCommServer`` / Sionna RT）与真实 **Wi-Fi / 5G / USRP** 无线电硬件之间零代码切换。

4. **可审计的动作与通信回执（Verifiable Receipts）**
   ``HarnessRuntime`` 为每一次改变世界状态的物理动作（ ``WORLD_MUTATING`` ）与每一次无线发包（ ``NETWORK_TX`` ）自动签发不可伪造的回执（ ``Receipt`` ），并全程审计观测新鲜度与调用闭合性（保证 ``violations == 0`` ），同时将评测真值严格隔离在服务端，杜绝任何隐式信息泄露。
